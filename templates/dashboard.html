How Blockchain Works

Blocks stored in Firestore

Each block contains an index, timestamp, transactions and a hash of the previous block. The chain is persisted in Firestore under the blockchain collection.

Proof of Work (difficulty: 4 zeros)

To create a new block, the system searches for a number (proof) so that SHA-256(last_proof || proof) begins with 0000. This secures the chain from easy tampering.

Transactions = Question records

When questions are added, a transaction with question ID, text, Bloom level and timestamp is appended to the latest block.

Verification

Verification walks the chain to ensure each block's previous_hash matches the SHA-256 of the prior block and that proofs satisfy the difficulty.

Verify Now

Genesis block is created automatically on first run. All subsequent blocks reference the hash of the previous block, forming an immutable chain.

Any mismatch in hashes or invalid proof indicates tampering, and the chain is flagged as invalid.
